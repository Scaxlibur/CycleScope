# CycleScope 文档规则

本页是 CycleScope 文档分类、事实来源、状态和迁移方式的规范入口。它适用于根目录 `README.md`、`docs/`、`final_doc/` 以及各源码子项目的维护型说明；赛题原件、主办方答疑、厂商资料和已经清单化的证据原件只受来源与不可变规则约束，不做正文改写。

## 页面类型

每篇维护型页面只承担一个主要读者目标。页面可以链接其他类型，但不借「概览」重复完整参数或执行记录。

| 类型 | 读者目标 | 允许内容 | 应链接到其他位置的内容 |
| --- | --- | --- | --- |
| Landing | 判断项目是否适用并找到起点 | 项目身份、适用范围、架构摘要、安全提醒、主要入口 | 完整参数、证据根、实现细节、历史过程 |
| Navigation | 按任务进入正确页面 | 阅读目的、页面说明、下一步 | 参数表、构建身份、验收流水 |
| Getting Started | 从安全状态获得首个明确结果 | 前置条件、线性步骤、预期结果、成功判据 | 参数全集、设计论证、历史记录 |
| How-to | 完成一个具体操作 | 风险、最短步骤、验证、常见失败 | 协议字段全集、架构历史 |
| Reference | 查询精确合同 | 参数、格式、输入输出、边界、错误语义、兼容性 | 教程叙事、里程碑、待办 |
| Concept | 理解系统为何这样设计 | 模型、数据流、取舍、限制 | 命令清单、字段全集、测试流水 |
| Development | 修改、测试或发布实现 | 开发流程、构建入口、测试门、维护规则 | 用户验收结论、原始实验记录 |
| Evidence index | 判断证据能证明什么 | 身份、适用范围、原始根和不能证明的内容 | 操作教程、重复参数说明 |
| Release | 查询冻结版本或构建身份 | Git tag、提交、BIN/ELF、Profile、审计绑定 | 开发分支进度、未验证能力 |
| RFC / Proposal | 审阅尚未落地的设计 | 问题、约束、方案、验收条件 | 当前能力承诺 |
| Historical | 追溯旧计划、失败或替代前实现 | 日期、身份、原始背景、替代入口 | 当前操作指引、当前支持结论 |

新增或大幅改写页面前，先在任务记录中写明页面类型、读者目标、适用状态、关键事实源和相关页面。只有非 Current、身份绑定或容易误用的页面才需要把这些信息显式写到页面顶部，避免为简单页面制造元数据负担。

## 状态与证据等级

- `Current`：已经存在于当前源码、冻结 Profile 或明确发布身份中。涉及硬件行为时，仍须单独说明证据等级。
- `Experimental`：可以构建或诊断，但默认关闭，稳定性或支持范围未冻结。
- `Proposed`：尚未实现、未发布或只有计划，不得写成「已通过」或「当前正式」。
- `Historical`：旧实现、旧校准、失败点、旧报告或已替代计划。页面顶部应给出当前入口，正文不能覆盖 Current 结论。

状态不能替代证据等级。例如，F0 两位小数显示是当前实现，但对应镜像只有构建、烧录和 100 帧烟测，不能因此取得旧 BIN 的 M8/M9 20 例审计身份。证据结论统一从[测试与证据索引](测试与证据索引.md)进入。

## 事实来源

事实冲突时，按本表回到机器事实或冻结证据，不用相邻文档互相证明。

| 事实 | 权威来源 | 文档规则 |
| --- | --- | --- |
| 赛题要求与计时口径 | `docs/G题_周期信号测量分析装置/` 与 `docs/主办方答疑/` 原件 | 项目文档只解释采用方式，不改写原件 |
| 正式发布身份 | Git annotated tag、对应提交及发布证据 | `main`、本地工作树和 tag 不能互相代替 |
| FPGA 冻结基线 | `fpga-v1.0.0@038e981` 及其 M14 证据 | 当前入口为 [FPGA 验收证据索引](FPGA验收证据索引.md) |
| PL RTL、器件、引脚与时序 | `Zynq_7010_PL/rtl/`、`constraints/`、`scripts/` | Guide 只保留构建入口和解释，不手工维护第二份实现表 |
| PL 与 PS 接口 | `Zynq_7010_PL/docs/PL-PS接口契约.md` 及对应 RTL | 其他页面链接该合同 |
| CSLP 字节格式与状态机 | `Zynq_7010_PS/cyclescope_cslp/include/cslp_protocol.h`、实现和协议测试 | [CSLP UDP 协议](协议与接口/CSLP-UDP-通信协议-v0.1.md)是人工 Reference，必须随实现核验 |

| 网络默认值 | P4 `Kconfig.projbuild`、接收器常量和 PS 发送端配置 | 示例地址与正式地址必须显式区分 |
| P4 接收、FFT 与 UI 行为 | `ESP32-P4/main/app/` 及对应主机测试 | Concept 和 How-to 不复制易变实现状态 |

| M12 工程联调 | M12 审计 JSON 及其 `SHA256SUMS` | 只证明 60 个 P4 工程联调观测点，不替代模拟链标定或镜像发布审计 |
| M8/M9 发布审计 | `final-p4-release-audit-20260801_190121+0800/` | 20/20 结论只绑定 BIN `d819641d…d8207007` |
| F0 显示镜像 | `docs/evidence/F0显示版构建烧录证明/release-record.json` | BIN `e30d16c4…a4bac0e` 只具有该记录声明的烟测范围 |
| 最终报告正文 | `final_doc/设计报告.md` | `设计报告.html` 是独立排版的派生预览，必须通过同步检查 |
| 当前公开限制 | [测试与证据索引](测试与证据索引.md)及其所指证据 | 内部恢复细节留在 `tool-of-rei/`，不进入 Landing |

易变化的事实只在权威来源完整维护一次。Landing、Navigation、Concept 和 How-to 可以摘要，但应链接权威页，不复制整张参数表、哈希表或验收结果。

## 证据不可变边界

以下对象一旦带有 `SHA256SUMS`、manifest 或冻结身份，不得为整理文档而编辑、覆盖、改名、移动、重采替换或从摘要反推重建：

- `tool-of-rei/evidence/` 中的原始证据根；
- `source_data_for_test/` 中的回放包；
- `docs/evidence/` 中受原始根和清单约束的版本化副本；
- 失败、`INCOMPLETE`、450 mVpp 压缩点、旧校准与历史诊断证据；
- Git tag 与已发布构建身份。

需要补充时，只能新增独立证据根、更新导航索引，或新增一页说明并链接原根。摘要不能替代 pcap、波形、UART 日志、BIN/ELF 或 Flash 读回。

## 生命周期动作

每篇页面在一次迁移中只选择一个主要动作：

| 动作 | 使用条件 |
| --- | --- |
| `KEEP` | 职责清楚、事实可追溯、导航可达 |
| `REWRITE` | 路径与主职责保留，但正文需要围绕单一读者结果重写 |
| `SPLIT` | 同页混合多个独立读者目标或页面类型 |
| `MERGE` | 多页重复维护同一职责或易变事实 |
| `MOVE` | 内容职责正确，但目录或状态表达错误 |
| `GENERATE` | 内容可由稳定代码、schema 或单一正文确定性生成 |
| `ARCHIVE` | 内容仍有追溯价值，但不能作为当前事实源 |
| `DELETE` | 已被权威页面完整替代，且不属于证据、原件或历史记录 |

不因页面很长就自动拆分，不为目录对称创建空页面。`DELETE` 永不用于已清单化证据、失败记录、赛题/答疑、厂商原件或 Git tag。

## 修改流程

1. 先做局部审计，确认页面职责、入链、出链和事实源。
2. 先建立目标页，再迁移一类职责，并保留旧入口的有效链接。
3. 对协议、Profile、构建身份和量化结论回查代码、tag 或证据 JSON。
4. 运行文档链接与结构检查、派生产物漂移检查和 `git diff --check`。
5. 根据改动范围运行离线测试；文档任务默认不连接仪器、不下载 FPGA、不烧录 P4。
6. 页面结构与事实确定后，再检查中文表达；机器字面量、路径、字段、哈希和外部原件保持原样。
7. 一轮优先处理 2～4 个能验证设计的页面，完成验证后再处理下一领域。

本地命令和 CI 级别见[文档工作流](development/文档工作流.md)；当前证据的阅读顺序见[测试与证据索引](测试与证据索引.md)，详细原始根见[验收证据索引](验收证据索引.md)。
