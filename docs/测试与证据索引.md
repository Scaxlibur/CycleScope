# CycleScope 测试与证据索引

更新：2026-08-02
目的：把测量数据、运行数据、回放源、镜像身份和其适用范围放到同一入口。原始档案保留，历史流水保留；本文件不改写任何已哈希的原始记录。

## 先看这一条

[`evidence/`](evidence/) 只包含可版本化的轻量摘要。完整原始档案当前为 `3,413,342,059 B`（约 3.3 GB），位于 `tool-of-rei/evidence/` 的本机/外部归档中；真实 FPGA 回放源为 `264,897,911 B`（约 256 MiB），位于 `source_data_for_test/`。后者现有 124 个点级归档、124 份 `wire.pcap`；2026-08-02 已按历史记录精确恢复全部 manifest，并复核 620 条 SHA256SUMS。

因此，摘要用于快速审查，原始根与 SHA256SUMS 用于复核。不要用一个摘要 JSON 替代 pcap、波形、串口日志或烧录读回。

## 建议审查顺序

1. 阅读本文件和 [轻量证据摘要](evidence/README.md)，确定要回答的问题属于哪一类证据。
2. 对模拟链量值与补偿，先看“最终标定”，再看独立 holdout。
3. 对 P4 最终测量结论，使用“最终 M8/M9 审计”；它是唯一 20 例最终审计入口。
4. 对当前 F0 两位小数显示镜像，只使用“F0 显示版构建烧录证明”，并遵守其未重跑全矩阵的边界。
5. 对 DG→FPGA→LAN→P4 工程联调，使用 M12；不要把 M12 冒充为完整模拟前端标定。

## 原始证据的保存与校验

1. 原始根有 SHA256SUMS 时，在该根目录运行 sha256sum -c SHA256SUMS。
2. 不要移动、重命名或编辑已清单化的原始 JSON、日志、BIN、ELF、pcap、npy 或截图。
3. 需要外部备份时，保留整个证据根及层级；M12 还必须连同其引用的 m12-live-* 子包备份。
4. F0 显示版的版本化记录位于 `docs/evidence/F0显示版构建烧录证明/release-record.json`；该目录中的 SHA256SUMS 只校验版本化摘要，不会假装校验未随 Git 提交的 BIN/ELF。

更详细的证据根、历史负例和相邻 FPGA 工作树对照见 [验收证据索引.md](验收证据索引.md)。
