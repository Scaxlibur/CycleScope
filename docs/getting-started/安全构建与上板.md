# 安全构建与上板

本页提供从离线验证、完整构建到授权后上板的线性路径。前四节不连接仪器、不下载 FPGA、不烧录 ESP32-P4；第五节开始会改变真实硬件状态。

> [!CAUTION]
> 没有明确硬件操作授权时，在「上板前门禁」处停止。JTAG `--execute`、`idf.py flash`、串口打开、UDP 重放和信号源控制均不属于离线验证。

## 1. 前置条件

- Git 工作树位于 `main` 分支，且已识别现有未提交改动。
- PL/PS 构建使用 Vivado 与 Vitis 2025.1。
- ESP32-P4 构建使用 ESP-IDF 6.0.2。
- 主机具备 C/C++ 编译器、Bash 和 Python 3。

先在仓库根目录检查：

```bash
git status --short --branch
```

构建脚本会拒绝非 `main` 分支。若工作树包含不相关改动，先确认归属，不要重置或覆盖。

## 2. 离线验证

### 2.1 Zynq PL

```bash
make -C Zynq_7010_PL version
make -C Zynq_7010_PL sim
make -C Zynq_7010_PL synth
```

成功判据：仿真末尾出现 `ALL_SIM_TESTS_PASS`，滤波器与核心综合分别出现 `FILTER_SYNTH_PASS`、`CORE_SYNTH_PASS`，且时序余量非负。

### 2.2 Zynq PS 与 CSLP

```bash
make -C Zynq_7010_PS/cyclescope_cslp test
```

该命令只编译主机 C11 测试并运行 Python 单元测试。进程退出码为 0 且所有用例通过即为成功；它不会下载板卡或发送真实 UDP。

### 2.3 ESP32-P4 主机测试

```bash
bash tool-of-rei/test/run_g_parameter_sweep_host_test.sh
bash tool-of-rei/test/run_live_stream_freshness_host_test.sh
bash tool-of-rei/test/run_measurement_format_host_test.sh
bash tool-of-rei/test/final_calibration/run_frequency_response_host_test.sh
bash tool-of-rei/test/final_calibration/run_fft_frequency_response_host_test.sh
```

这些入口只在临时目录编译或读取本机代码，不打开串口、不发送网络包、不操作仪器。预期末尾分别出现 `passed` 或 `PASS`；完整夹具边界见仓库内 `tool-of-rei/test/README.md`。

## 3. 生成构建产物

### 3.1 PL 系统 XSA 与 PS ELF

```bash
make -C Zynq_7010_PL system
make -C Zynq_7010_PS/cyclescope_cslp vitis
```

`vitis` 依赖 `system` 生成的 `Zynq_7010_PL/build/system/hardware/cyclescope_system.xsa`。成功输出应包含 `SYSTEM_SYNTH_PASS`、`SYSTEM_XSA=...`、`VITIS_RTL8211F_FIXED_100_BACKEND_PASS`、`VITIS_BUILD_PASS` 和 `VITIS_APP_ELF=...`。

### 3.2 P4 fresh build

为避免复用本地 `.5` 或故障注入配置，为 build 和 `sdkconfig` 选择新的临时路径：

```bash
export CYCLESCOPE_P4_BUILD=/tmp/cyclescope-p4-formal-build
export CYCLESCOPE_P4_SDKCONFIG=/tmp/cyclescope-p4-formal-sdkconfig
export CYCLESCOPE_IDF_ROOT=/absolute/path/to/esp-idf-v6.0.2

source "$CYCLESCOPE_IDF_ROOT/export.sh"
(
  cd ESP32-P4
  idf.py -B "$CYCLESCOPE_P4_BUILD" \
    -D "SDKCONFIG=$CYCLESCOPE_P4_SDKCONFIG" \
    -D "CYCLESCOPE_LOCAL_TEST_CMAKE=" \
    build
)
```

构建后至少检查：

```bash
rg -n 'CONFIG_CYCLESCOPE_CSLP_PEER_IPV4' \
  "$CYCLESCOPE_P4_BUILD/config/sdkconfig.h"
rg -n '^CYCLESCOPE_LOCAL_TEST_CMAKE' \
  "$CYCLESCOPE_P4_BUILD/CMakeCache.txt"
sha256sum \
  "$CYCLESCOPE_P4_BUILD/CycleScopeP4.elf" \
  "$CYCLESCOPE_P4_BUILD/CycleScopeP4.bin"
```

正式 peer 必须为 `192.168.10.2`，本地测试片段必须为空。发现 `.5`、fault fixture、diagnostic consumer 或本地测试 CMake 时，不得把该产物用于正式联调。

### 3.3 PL bitstream

```bash
make -C Zynq_7010_PL bitstream
```

只有 `SYSTEM_IMPLEMENTATION_PASS` 与 `BITSTREAM_XSA_CONTENT_PASS` 同时出现，才获得进入 JTAG dry-run 的条件。

## 4. JTAG dry-run

以下命令只核对 bitstream、`ps7_init.tcl`、ELF、工具版本、分支和操作计划，不连接硬件：

```bash
/tools/Xilinx/2025.1/Vitis/bin/xsdb -no-ini \
  Zynq_7010_PS/cyclescope_cslp/scripts/jtag_download.tcl
```

成功判据为 `CYCLESCOPE_JTAG_DRY_RUN_PASS`。dry-run 不需要启动 `hw_server`，也不构成真实下载授权。

## 5. 上板前门禁

进入真实操作前，逐项确认：

- 已取得本次 JTAG、P4 Flash 和串口操作授权；
- 信号源输出为 OFF，接线、共地、50 Ω 条件和输入范围已确认；
- FPGA、P4 和电脑位于约定的隔离网络，电脑没有占用 UDP 50000/50001；
- bitstream、ELF、P4 BIN 和配置来自刚完成并记录哈希的构建；
- JTAG dry-run 已通过，目标 cable 和 P4 串口身份已确认；
- 若曾执行 MIO47 PHY 复位实验，板卡已经彻底断电并等待电源放净后重新上电。

任一条件不满足时停止，不用一次旧 PASS 推断当前硬件安全。

## 6. 授权后的真实操作

### 6.1 Zynq JTAG 下载

先启动 Vivado 2025.1 `hw_server`，再执行带 `--execute` 的下载：

```bash
/tools/Xilinx/2025.1/Vivado/bin/hw_server -L- -stcp::3121 -p0
```

```bash
/tools/Xilinx/2025.1/Vitis/bin/xsdb -no-ini \
  Zynq_7010_PS/cyclescope_cslp/scripts/jtag_download.tcl \
  --execute
```

该命令会复位系统、配置 FPGA、初始化 PS、下载 ELF 并继续 A9#0，但不写 QSPI。成功判据为 `CYCLESCOPE_JTAG_DOWNLOAD_PASS`。

### 6.2 ESP32-P4 烧录

```bash
export CYCLESCOPE_P4_UART=/dev/serial/by-id/<verified-cp2102n-device>
(
  cd ESP32-P4
  idf.py -B "$CYCLESCOPE_P4_BUILD" \
    -p "$CYCLESCOPE_P4_UART" \
    flash
)
```

烧录会写 Flash 并复位 P4。bootloader、partition table 和 app 三段都应完成写后校验；需要冻结发布身份时，还要按 BIN 实际大小读回 app 分区并执行 `cmp` 与 SHA-256 对比。

## 7. 启动验证与停止条件

P4 启动后应依次看到 UI/FFT 自检、以太网 Link Up、生产地址 `.3:50001 → .2:50000`、CSLP 会话和新鲜测量帧。若 FPGA 尚未监听，握手超时只表示对端未就绪，不能单独判定协议实现失败。

出现以下任一情况立即停止后续测试并恢复安全状态：

- 接线、设备身份或网络角色与记录不一致；
- P4 构建包含 `.5`、故障注入或诊断消费者；
- OTR、FIFO、CRC、分片、过流、过温、WDT、panic 或 assert 异常；
- 信号源输出状态无法确认；
- 当前结果无法绑定到刚记录的构建和证据根。

协议参数见 [G 题 Profile](../协议与接口/CSLP-G题采样与处理-Profile-v0.1.md)，两板启动顺序见 [FPGA 与 ESP32-P4 联调](../how-to/FPGA与ESP32-P4联调.md)，详细 P4 配置与日志判断见 [ESP32-P4 端联调指南](../系统补偿方案/ESP32P4-FPGA联调指南-ESP32P4端.md)，证据记录规则见[测试与证据索引](../测试与证据索引.md)。
