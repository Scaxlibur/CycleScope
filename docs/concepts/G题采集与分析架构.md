# G 题采集与分析架构

> 类型：Concept；状态：Current。精确固定值以 [G 题采样与处理 Profile](../协议与接口/CSLP-G题采样与处理-Profile-v0.1.md)为准，线上字节合同以 [CSLP UDP 通信协议](../协议与接口/CSLP-UDP-通信协议-v0.1.md)为准。

本页解释 CycleScope 为什么将采集、传输、分析和显示分配给不同处理器，以及抽取、谐波识别和 latest-wins 如何共同满足 G 题实时测量要求。

## 问题约束

| 赛题要求 | 系统含义 |
| --- | --- |
| 被测分量位于 10～200 kHz 或 10～500 kHz | 有效测量带覆盖 10～500 kHz |
| 存在 200 mVpp、频率不低于 1 MHz 的单频干扰 | ADC 前后都要限制带外能量，避免抽取折叠 |
| 频率分辨率 500 Hz | FFT 原生栅格不大于 500 Hz |
| 电压和谱线幅值误差不大于 5 mV | 模拟、ADC、滤波、校准和估计误差共同受控 |
| 基频误差不大于 1 kHz | 必须识别谐波族，不能把最大谱峰直接当作 H1 |
| 按键后 2 秒内显示 | 系统提前建链并持续分析；按键后只切换当前或下一结果的呈现 |

50 Ω 输入、单路 5 V 和不小于 6 英寸的显示屏属于整机条件，不能由数字协议或软件日志代替验证。

## 数据流

```text
BNC / 模拟前端
    ↓
AD9226 通道 A，12 bit，65 MSPS
    ↓
Zynq PL：码型归一化 → 三级低通 → 16 倍抽取
    ↓ 4.0625 MS/s，8192 个连续 S16 样点
PL 双缓冲 → AXI-Stream → Clock Converter → S2MM DMA
    ↓
Zynq PS：帧元数据 → CSLP 分片 / CRC → 100M UDP
    ↓
ESP32-P4 Core 1：重组 → FFT → 谐波族 → Vpp / 真 RMS / F0
    ↓ 深度 1 的最新结果
ESP32-P4 Core 0：1P / 3P、频谱和 LVGL 交互
```

诊断构建可以在主发送成功后向电脑 `.4:50002` 镜像同一应用载荷。镜像只用于观测，P4 仍是唯一控制端。

## 为什么由 FPGA 先滤波和抽取

65 MSPS 原始流不适合直接交给 P4 实时接收和显示。取 16 倍抽取后：

```text
Fs = 65,000,000 / 16 = 4,062,500 Hz
Δf = Fs / 8192 = 495.91064453125 Hz
```

该组合同时满足频率栅格要求，并把单帧数据固定为 16 KiB。三级 FIR 必须位于抽取之前；直接每 16 点取 1 点会将带外能量折叠到 0～500 kHz。

数字滤波只处理已经被 ADC 采到的离散信号。高于 32.5 MHz 的模拟能量可能在 65 MSPS 采样前折叠，因此模拟前端仍需抗混叠，不能把 P4 的 500 kHz 搜索上限当作模拟滤波器。

## 为什么使用快照而不是原始连续流

单个 8,192 点采集窗约 2.016492 ms，系统每 50 ms 投递一个最新快照。这样可以：

- 保持 20 frame/s 的更新节奏；
- 为 FPGA、网络、FFT 和 UI 留出调度余量；
- 避免将近 496 frame/s 的可形成窗口全部塞入百兆链路；
- 在拥塞时丢弃过时快照，而不是累积无界队列。

## 基频、幅值和波形

P4 对每帧先按标定元数据换算到 BNC 输入端电压、去直流并乘 Hann 窗，再计算 8,192 点 FFT。正频谱使用窗函数实际和归一化，避免把 Hann 相干增益损失写入谱线幅值。

候选只在 10～500 kHz 搜索。算法先做三点插值，再以直接正弦投影细化频率、幅值和相位；随后按整数倍关系组成谐波族。因此强高次谐波可以高于 H1，而不会被直接误判为基波。

正式测量使用 H1 和最强两条合法谐波：

```text
u(t) = Σ Aᵢ sin(2πhᵢf₀t + φᵢ)
RMS  = sqrt(Σ Aᵢ² / 2)
Vpp  = max(û) - min(û)
```

Vpp 必须保持各分量相位后重构，不能用 `2 × ΣAᵢ`；真 RMS 也不能用 `Vpp/(2√2)` 的单正弦近似。TIME 页使用 H1 相位在 Hann 窗中心附近选择统一上升过零锚点，再分别生成 1P 和 3P 保峰投影。

## 帧所有权与过载策略

网络到分析使用三个预分配帧槽：

```text
assembling → latest → in_use
```

- 接收任务只写 `assembling`，完整且合法后原子发布为 `latest`。
- 分析任务 acquire 后只读 `in_use`，结束时显式 release。
- 尚未 acquire 的旧 `latest` 可以被新帧覆盖；`in_use` 绝不改写。
- 发布结果前再次检查 session、config 和 stream epoch，断链后的旧结果不能成为 current。
- 分析到 UI 也使用深度 1 的 latest-result 队列，优先显示最新状态。

latest-wins 是实时显示策略，不表示网络丢包。需要逐帧审计时，应使用接收、完成、分析和发布计数判断数据链，而不是要求 UI 显示每一帧。

## 任务边界

| 业务任务 | 核 | 相对优先级 | 职责 |
| --- | ---: | ---: | --- |
| Ethernet RX | 系统配置 | 最高 | 驱动与 lwIP 收包 |
| `cslp_udp_rx` | Core 1 | 6 | 来源、CRC、分片、重组和帧发布 |
| `cs_analyze` | Core 1 | 4 | FFT、谱峰、Vpp/RMS/F0 和投影 |
| LVGL worker / UI | Core 0 | Adapter 默认 | 触摸、刷新和所有 LVGL API |

必须保持 `receiver_priority > analysis_priority`。接收任务阻塞在 `recvfrom` 时不占用 Core 1；分片到达后立即抢占分析任务，排空 socket 后再让分析继续。网络任务不得执行 FFT 或 LVGL，UI 也不得直接读取网络帧槽。

## 吞吐预算

每帧包含 16,384 byte 样点；加上 12 个 WAVE_DATA 头后，UDP 应用数据为 17,248 byte。按无 VLAN 且计入以太网头、FCS、前导码和帧间隙估算：

- 单目的 20 frame/s 约占 2.8864 Mbit/s；
- 诊断双发约占 5.7728 Mbit/s；
- 两者均远低于 100 Mbit/s 标称带宽。

实际风险来自 pbuf、TX descriptor、socket 和任务调度，而不是平均带宽。固定 500 us 分片调度用于压低突发；普通电脑 pcap 时间戳会受 NAPI 合并影响，不能作为物理线上最小包间隔证明。

## 设计边界

- FPGA 的唯一正式对外数据通道是 LAN；保留的 SPI 资产只解释历史证据。
- Zynq 固定使用 100BASE-TX Full，但保留 PHY 自协商并只广告 100M Full。
- P4 使用 ANSI FFT 内核；恢复 ARP4 前必须重新通过弱基波、边界、性能和长稳验证。
- 软件回调、UI bridge 和截图只能证明软件阶段，不能证明按键到真实 panel flush 的时限。
- 实现性能和历史验收数值见[实施与验收历史](../history/CSLP-G题-Profile-v0.1-实施与验收记录.md)，不在 Concept 中维护。
