# ESP32P4-FPGA 联调指南（FPGA 端）

## 1. 文档定位与当前状态

本文从 Zynq-7010 的 PL＋PS 行为出发，说明 ESP32-P4 从 FPGA 收到的究竟是什么、这些
样点已经经历了哪些处理，以及 P4 在电压换算、FFT、逐频补偿和异常门禁中还需要做
什么。

当前 8192 点 FPGA 版本已完成真实 ADC、模拟前端、LAN 双目的地、ESP32-P4 联合验收和
PS＋PL QSPI 掉电启动验收，通信链路已联通。正式可恢复基线是：

- Git tag：`fpga-v1.0.0`
- Git commit：`038e981`
- 固定 Profile：8192 点、4.0625 MS/s、20 frame/s、单通道、S16_LE
- 数据接口：CSLP v0.1 over UDP/LAN

本文只描述 `fpga-v1.0.0@038e981` 的固定 8192 点线上能力。P4 当前也不需要、
不应依赖 SPI 接口；LAN 是双方唯一需要维护的联调和数据通道。

## 2. 一页结论

P4 收到的不是 65 MSPS 原始 ADC 数据，也不是 FPGA 算好的 FFT 结果，而是：

> AD9226 通道 A 的 12 bit 原始码，经 FPGA 位序/码型归一化、三级 FIR 低通、16 倍
> 抽取、四舍五入和 S16 饱和后形成的 8192 个连续有符号码值，再由 Zynq PS 封装为
> 12 个 CSLP WAVE_DATA UDP 数据报。

P4 必须牢记以下边界：

1. 线上样点率是 `4,062,500 sample/s`，不是 `65,000,000 sample/s`。
2. 一帧 8192 点内部连续，采集窗是 `2.016492 ms`；帧起点每约 `50 ms` 出现一次。
3. 相邻帧之间约有 `47.98 ms` 未上传数据，不能拼成连续 16384 点做 FFT。
4. 载荷仍是 ADC/FIR 码值，不是微伏；按每帧元数据执行
   `u_uV = code × scale_uV_per_lsb + offset_uV`。
5. 当前正式标量身份为 `calibration_id=25030`、`516 µV/code`、`-6761 µV`。
6. `CALIBRATED` 只表示上游标量校准有效；P4逐频补偿还要求匹配的 `C5DCDE41` 资产，并在日志/结果中显示 `p4cal=1`。
7. FPGA 不发送频率、幅值、RMS、Vpp、谐波或题目答案；这些都由 P4 从完整帧计算。
8. 带 `ADC_OVERRANGE`、`FIFO_OVERFLOW` 或 `TEST_PATTERN` 的帧不得发布为正常测量。

## 3. 从 BNC 输入到 P4 的真实信号链

```text
BNC 输入信号
    ↓
AD8065 模拟前端＋50 Ω匹配网络
    ↓  真实模拟放大和频率响应发生在这里
AD9226 通道 A，65 MSPS，12 bit offset binary
    ↓
Zynq PL：输入寄存 → 码型归一化 → 三级FIR → /16抽取 → 8192点帧
    ↓
AXI-Stream → DMA → DDR
    ↓
Zynq PS：冻结帧级元数据 → CSLP分片 → UDP主发＋电脑镜像
    ↓
ESP32-P4：校验/重组 → 码值转输入端电压 → FFT/投影 → 逐频补偿 → 测量/UI
```

AD8065 前端的理论反馈增益约为 `9.031968 V/V`；在理想的输出串联 50 Ω、ADC 端 50 Ω
加载模型下，ADC 节点的理论增益约为 `4.515984 V/V`。这两个数只用于拓扑理解和量程
预算，P4 不得再用它们除一次样点。当前 CSLP 标量校准已经折算到 DG 50 Ω设置/BNC
输入基准，包含实际模拟前端和 ADC 链的端到端关系。

也就是说，P4 的正式幅值换算依据是 WAVE_DATA 元数据，不是 AD9226 的名义
`2.44140625 mV/code`，也不是理论 `4.515984` 倍增益。前端接线、量程、安全边界和校准
过程见《信号前端测量方案》和《前端增益与逐频补偿指南》。

## 4. FPGA 对 ADC 样点做了什么

### 4.1 通道、位序和码型

正式链路只采集 AD9226 通道 A。通道 B 不参与交织、平均、拼接或发送。

当前位序是：

```text
A1 = D0 / LSB
...
A12 = D11 / MSB
```

当前固化参数为：

| 参数 | 值 | 含义 |
|---|---:|---|
| `ADC_OFFSET_BINARY` | `1` | 输入按 offset binary 解释 |
| `ADC_REVERSE_BITS` | `0` | 不反转 12 根数据线 |
| `INVERT_POLARITY` | `0` | 不额外反相 |

位序整理后的 12 bit 原始码按下式转为有符号码：

```text
signed_code = raw_code - 2048
```

典型映射为：

| AD9226 原始码 | 归一化码 |
|---:|---:|
| `0` | `-2048` |
| `2048` | `0` |
| `4095` | `2047` |

因此 P4 收到 S16_LE 样点后，不得再次减 2048、反转 bit、反相、除以 16 或左移 4 位。
这些重复处理会制造非常像“ADC 接线错了”的假故障，实际上只是软件把正确数据又处理
坏了一遍。

原始 ADC 尺度是 `-2048..2047`，但 FIR 输出按完整有符号 16 bit 协议传输。滤波瞬态或
叠加信号可能使输出超出 12 bit 原始范围，因此 P4 不能以“样点绝对值大于 2048”为由
直接判定协议错误。

### 4.2 三级 FIR 和 16 倍抽取

FPGA 使用三级线性相位 Q1.17 FIR：

| 级 | taps | 本级抽取 | 输入/输出样点率 |
|---:|---:|---:|---:|
| 1 | 21 | `÷4` | 65 MS/s → 16.25 MS/s |
| 2 | 31 | `÷4` | 16.25 MS/s → 4.0625 MS/s |
| 3 | 79 | `÷1` | 4.0625 MS/s → 4.0625 MS/s |

每级系数和均为 `2^17`，数字直流增益为 1。每级使用 48 bit 累加，结果四舍五入并饱和
到 S16，不做二进制回绕。抽取只改变样点率，不把样点幅度乘 16 或除 16。

当前滤波器的用途是抗混叠和抑制高频干扰：

- 有效测量通带：`0～500 kHz`
- 理论/复算通带纹波：`0.019259 dB`
- 全混叠路径最差阻带：`-67.610974 dB`
- 真实前端 1～3 MHz 测试最差衰减下界：`72.337599 dB`
- 真实前端 4～10 MHz 测试最差衰减下界：`65.996983 dB`

FPGA FIR 不执行 AD8065 增益补偿，也不执行 10～500 kHz 的逐频逆补偿。1 MHz 以上的
残余信号已经处于阻带/混叠语义，P4 不得对它做逆补偿并把噪声重新放大。

### 4.3 固定群延迟与时间戳

三级 FIR 的总群延迟按 65 MHz 原始时钟计为：

```text
10 + 15×4 + 39×16 = 694 tick
694 / 65 MHz = 10.676923 µs
```

PL 把首个输出样点对应的原始 ADC 时钟锚点交给 PS，FPGA/PS 已在 WAVE_DATA 的
`timestamp_us` 中补偿这 694 tick。P4 不得再次扣除滤波群延迟。

`timestamp_us` 表示该帧第一个输出样点的等效 ADC 采集时刻。第 `n` 个样点的时刻为：

```text
t_us[n] = timestamp_us + n × 1,000,000 / 4,062,500
```

样点间隔约为 `0.246153846 µs`，小于时间戳的 1 µs 分辨率。P4 应用采样率计算相对
时间，不能把时间戳按整数微秒逐点累加。

## 5. 帧的真正含义

### 5.1 8192 点窗口与 50 ms 周期不是一回事

当前固化 PL 每 `3,250,000` 个 65 MHz 时钟发起一次捕获，即约每 `50 ms` 形成一帧。
每帧包含 8192 个抽取后连续样点：

```text
采集窗时长 = 8192 / 4,062,500
           = 2.016492307692 ms
```

帧内第一个到最后一个样点的时间跨度是 `8191 / 4,062,500`，完整采样窗口按 `N/Fs`
记为 `2.016492 ms`。

```text
帧k：   [8192个连续点，约2.016 ms]........约47.98 ms未上传........
帧k+1：                                                  [8192个连续点]
```

所以：

- 一帧内部可以直接进行 8192 点 FFT、正弦拟合或谱线投影。
- 8192 点 FFT 的 bin 间隔为 `4,062,500 / 8192 = 495.91064453125 Hz`；精确频率仍应
  通过插值或已知频率投影精修，不能只返回整数 bin 中心。
- 相邻帧起点的时间戳约相差 50 ms，而不是 2.016 ms。
- 两帧不是同一段连续波形，不能拼接为 16384 点连续 FFT。
- 丢帧后不得用上一帧重复填充，也不得用插值伪造缺失的约 48 ms 波形。
- UI 显示最新一帧即可；跨帧统计应统计“多次独立测量”，不能假装成一条连续时域记录。

### 5.2 首帧延迟

FPGA 只有在 P4 完成 `HELLO → CONFIG_SET → ENABLE_PUSH` 后才开始正式推送。当前实测
首个完整帧延迟约 `58.438 ms`，主要由 50 ms 捕获等待、2.016 ms 采集窗和分片发送
组成。这是正常行为，不能用“ENABLE 后 10 ms 内未见完整帧”判为掉线。

## 6. P4 收到的 UDP 数据

### 6.1 固定网络角色

| 节点 | IPv4/端口 | 角色 |
|---|---|---|
| Zynq PS | `192.168.10.2:50000` | 控制响应、状态和波形发送 |
| ESP32-P4 | `192.168.10.3:50001` | 唯一控制端、主波形接收端 |
| 调试电脑 | `192.168.10.4:50002` | 被动镜像接收，不建立第二 session |

当前为 100BASE-TX Full 通信 Profile，保留以太网自协商。主目的地先发送，随后将相同
CSLP 应用字节 best-effort 镜像给电脑。镜像失败不应阻塞 P4，电脑也不能以镜像端身份
控制 FPGA。

P4 和电脑看到的 CSLP 应用报文相同，但 IP/UDP 目的地址不同。P4 不需要为“双目的地”
增加任何协议分支；它仍是唯一 session 和配置的所有者。

### 6.2 当前 CONFIG Profile

P4 应显式请求并核对 CONFIG_ACK：

| 字段 | 固定值 |
|---|---:|
| `sample_rate_hz` | `4,062,500` |
| `frame_sample_count` | `8,192` |
| `frame_period_us` | `50,000` |
| `sample_format` | `1`（S16_LE） |
| `channel_count` | `1` |
| `filter_profile` | `1` |

上电后 FPGA 处于 IDLE，不会自行发送波形。标准流程是：

```text
HELLO → HELLO_ACK
CONFIG_SET → CONFIG_ACK
ENABLE_PUSH → ENABLE_PUSH_ACK
WAVE_DATA / STATUS
```

改变配置时必须执行 `DISABLE_PUSH → CONFIG_SET → ENABLE_PUSH`。重连必须生成新的非零
`session_id`，不能沿用旧 session/config。

### 6.3 一帧如何分包

WAVE_DATA 使用 72 byte 头，UDP 应用载荷上限为 1472 byte。单通道 S16 每点 2 byte，
因此满包携带 700 点：

| 分片 | `chunk_index` | `sample_offset` | `samples_in_chunk` | UDP应用字节 |
|---|---:|---:|---:|---:|
| 0～10 | 0～10 | `index × 700` | 700 | 1472 |
| 11 | 11 | 7700 | 492 | 1056 |

一帧共 12 个 WAVE_DATA，精确覆盖 `[0, 8192)`，样点应用数据总量为 16,384 byte，含
WAVE 头的应用数据总量为 17,248 byte。当前实现的分片发送起点间隔为 500 µs。

主目的地平均链路负载约 `2.8864 Mbit/s`，双目的地合计约 `5.7728 Mbit/s`，远低于
100 Mbit/s。WAVE_DATA 不提供 ACK、重传或背压；缺包时丢弃整帧，等待下一帧即可。

### 6.4 字节序和样点解码

- CSLP 公共头和 WAVE 扩展头的多字节字段：网络字节序（大端）。
- 波形载荷：S16_LE（小端二补码）。
- 每个 UDP 数据报有独立的 CRC-32/ISO-HDLC。
- UDP checksum 为非零有效值，不使用 IPv4 分片。

不依赖未对齐指针时，单个样点可按下式解码：

```c
uint16_t bits = (uint16_t)payload[2 * i]
              | ((uint16_t)payload[2 * i + 1] << 8);
int16_t code = (int16_t)bits;
```

这一步已经得到最终有符号码；不要再做 offset-binary 转换。

### 6.5 WAVE 元数据意味着什么

同一帧的所有分片必须共享以下字段：

```text
session_id, timestamp_us, frame_id, chunk_count,
sample_rate_hz, frame_sample_count, sample_format, channel_count,
scale_uV_per_lsb, offset_uV, config_id,
filter_profile, calibration_id
```

除 `FIRST_CHUNK` 和 `LAST_CHUNK` 外，同一帧 flags 也必须一致。当前真实 ADC 正式帧的
正常核心标志应包含：

```text
FILTERED   = 0x0004
CALIBRATED = 0x0008
```

`TEST_PATTERN`、`ADC_OVERRANGE` 和 `FIFO_OVERFLOW` 正常情况下应为 0。首包和末包再分别
叠加 `FIRST_CHUNK=0x0001`、`LAST_CHUNK=0x0002`。

`timestamp_us` 是采样时刻，不是 UDP 到达时刻；`frame_id` 是帧身份；`message_seq` 是
每个 WAVE 数据报的序号。三者不能混用。

## 7. 码值如何换成输入端电压

### 7.1 当前标量校准身份

当前 QSPI 固化版本的正式 WAVE 元数据为：

| 字段 | 当前值 | 语义 |
|---|---:|---|
| `calibration_id` | `25030` | AD8065＋AD9226＋FPGA链校准身份 |
| `scale_uV_per_lsb` | `516` | 折算到 DG 50 Ω设置/BNC输入基准 |
| `offset_uV` | `-6761` | 同一输入基准的零偏 |
| `filter_profile` | `1` | 500 kHz通带、16倍抽取 |

P4 应按每帧字段计算：

```text
u_input_uV = int64(code) × 516 - 6761
u_input_V  = u_input_uV × 1e-6
```

更通用的实现应读取字段，而不是把数字静默写死：

```text
u_input_uV = int64(code) × scale_uV_per_lsb + offset_uV
```

同时把 `25030/516/-6761/filter_profile=1/8192/4,062,500` 作为当前冻结身份门禁。若字段
变化，P4 应停止发布正式测量或明确显示“未校准/身份不匹配”，不能继续套用旧参数。

`offset_uV` 对显示真实时域波形和直流分量有意义。若只计算交流频谱，应先把整帧换算为
电压，再求均值并去直流；常量偏置会自然抵消。

### 7.2 `CALIBRATED` 不等于逐频补偿完成

当前 FPGA/PS 在线执行的只有标量身份注入。10～500 kHz 的完整响应保存在校准
`response.csv` 中，FPGA 和当前 P4 在线代码都没有执行逐频补偿。

正确的 P4 处理顺序是：

```text
S16码值
  → 按WAVE元数据转为输入端电压
  → 去直流
  → 加窗FFT/谐波族搜索
  → 精修每条谱线频率
  → project_at_frequency()取得幅值和相位
  → 按频率插值补偿该谱线幅值
  → 用补偿后的分量重算RMS、Vpp和显示结果
```

对频率为 `f` 的谱线，当前标量参考 `Sref=516 µV/code`，校准表给出
`S(f)=input_uv_per_code`：

```text
K(f) = S(f) / 516
A_corrected(f) = A_scalar(f) × K(f)
```

实现约束：

- 只在 `10～500 kHz` 内对 `input_uv_per_code` 做分段线性插值。
- 区间外不外推；1 MHz 以上阻带残余绝不做逆补偿。
- 不能给每个时域样点按“它自己的频率”乘不同系数；时域样点没有单一频率标签。
- 多音 Vpp 应由补偿后的幅值和原相位重建波形后计算；真 RMS 可由各正交谱线合成。
- 基波可能不是全谱最大峰，必须搜索满足题目约束的谐波族，不能把最大 FFT bin 永久
  写成基波。
- P4 运行时查表资产应从已验证的 `response.csv` 自动生成，并绑定
  `calibration_id` 和文件 SHA-256；不要手抄出第二份会悄悄漂移的表。

作为量级参考，100 kHz 的补偿因子约 `0.999486`，500 kHz 约 `1.016690`。500 kHz
若只用 516 标量而不补偿，误差已经可能接近项目 5 mV 门限，不能一概忽略。

## 8. P4 接收、重组和发布门禁

### 8.1 数据报级

收到数据报后至少检查：

- 源地址必须为 `192.168.10.2:50000`。
- magic、版本、头长、总长、payload 长度和消息类型合法。
- `session_id` 属于当前已 ready 的会话。
- CSLP CRC-32/ISO-HDLC 正确；UDP checksum 由网络栈校验。
- WAVE 头为 72 byte，单包不超过 1472 byte，无 IPv4 分片。
- reserved flags 为 0。

CRC 错误、旧 session、旧 config 和非法长度数据报直接丢弃，不能进入帧缓冲或 FFT。

### 8.2 帧级

P4 应用分片位图按 `frame_id` 重组，并检查：

- `chunk_count=12`。
- 非末包 700 点，末包 492 点。
- `sample_offset=chunk_index×700`。
- 12 个分片精确覆盖 8192 点，无空洞、重叠或冲突重复。
- 所有共享元数据完全一致。
- `config_id` 等于最近 CONFIG_ACK 返回值。
- Profile 六字段与当前固定配置一致。
- `FILTERED`、`CALIBRATED` 和校准身份符合正式测量要求。

网络可能造成乱序和重复，接收端需要容忍内容一致的重复分片；冲突重复应使整帧失效。
当前发送端不主动交错两个 frame_id，但接收端看到更新帧时可以丢弃未完成旧帧，采用
latest-frame-wins，不能让接收任务被坏帧长期卡住。

只有完整帧才能原子发布给分析任务。FFT、测量和 LVGL 不得直接读取仍在写入的重组
缓冲。

### 8.3 测量资格

| 条件 | 处理 |
|---|---|
| `ADC_OVERRANGE=1` | 可保存诊断，禁止发布正常测量 |
| `FIFO_OVERFLOW=1` | 可保存诊断，禁止发布正常测量 |
| `TEST_PATTERN=1` | 只用于数字联调，禁止冒充真实 ADC |
| `FILTERED=0` 或 `filter_profile!=1` | 禁止正式测量 |
| `CALIBRATED=0` 或 `calibration_id=0` | 可显示原始/未校准数据，禁止宣称正式精度 |
| 校准字段与冻结身份不符 | fail-closed 或明确显示未校准 |
| 缺包、元数据冲突、CRC错误 | 丢弃整帧，不进入分析 |
| FFT/投影失败或结果非有限 | 保留最近有效值并显示异常，不发布错误新值 |

`ADC_OVERRANGE` 来自 AD9226 OTR，在整帧期间锁存；`FIFO_OVERFLOW` 表示数字采集、DMA
或缓冲链来不及处理。两者不是同一种故障，P4 日志和计数器也不要合并。

STATUS 只能证明 FPGA/session 尚在线，不能证明波形数据仍新鲜。超过规定时间没有新的
完整有效帧时，UI 必须进入 STALE；旧测量值可以保留但必须明确标旧。发现
`device_boot_id` 改变或连续 3 个 STATUS 周期没有合法 STATUS/WAVE 时，清空旧会话状态
并重新握手。

## 9. 推荐的 P4 最小联调流程

1. P4 使用静态地址 `.3:50001`，确认只接受 `.2:50000`。
2. 生成新的非零 `session_id`，完成 `HELLO → CONFIG_SET → ENABLE_PUSH`。
3. 对 CONFIG_ACK 逐字段核对 4.0625 MS/s、8192、50 ms、S16_LE、1 通道、filter 1。
4. 等待首个完整 12 包帧；ENABLE 后约 58 ms 才得到完整首帧属于正常范围。
5. 先只验证分片、CRC、frame/config、flags、时间戳和 S16_LE 码值，不急着调 FFT。
6. 按 `code×516-6761` 交叉检查时域电压，并确认未再次做 offset-binary 或增益除法。
7. 每个 8192 点帧独立完成去直流、FFT、频率精修和谱线投影。
8. 导入与 `calibration_id=25030` 绑定的响应资产，补上 10～500 kHz 逐频幅值校正。
9. 用补偿后的谱线重算 RMS/Vpp，再原子发布测量和 UI 数据。
10. 验证缺片、CRC、OTR、FIFO、旧 session/config、FPGA 重启和数据停止时均 fail-closed。

双方通信已经完成联合验收，所以新问题应优先按“哪个处理层的语义不一致”定位，别一
看到数值不对就从 PHY 开始乱翻。链路通和测量正确是两件事，协议门禁就是把它们隔开。

## 10. 常见误区与快速定位

| 现象 | 首要检查 |
|---|---|
| 频率恰好差 16 倍 | P4 是否把 65 MSPS 当成线上采样率 |
| 波形整体偏置约 6.761 mV | 是否遗漏 `offset_uV=-6761` 或重复去偏置 |
| 幅值差约 4.5 倍 | 是否又除以 AD8065 理论增益，或误用了 ADC 端名义 LSB |
| 码值符号/中点明显错误 | 是否再次减 2048、翻转 bit、反相或移位 |
| 每两帧拼接处跳变、FFT杂散很大 | 是否错误拼接了相隔约 48 ms 的两帧 |
| 16384 点拼接 FFT 看似分辨率变高但结果飘 | 两个 8192 帧不是连续采样，方法本身无效 |
| 500 kHz 幅值有系统误差 | 检查 `p4cal=1`、profile `C5DCDE41`、六字段身份及带内查询是否成功；不要对带外分量逆补偿 |
| 1 MHz以上出现小残余谱线 | 这是 FIR 阻带/混叠残余；不要逆补偿 |
| 基波识别成更强的高次谐波 | 不要只取最大 bin，应搜索合法谐波族 |
| session ready 但没有波形 | 是否完成 ENABLE；首帧是否等够约 60 ms；分片门禁是否拒绝 |
| STATUS 正常但画面不更新 | 检查完整帧、分析和 UI 发布的新鲜度，不要把 STATUS 当新数据 |
| 偶发缺帧 | WAVE 无重传；丢弃不完整帧并等下一帧，检查接收任务是否被 FFT/UI 阻塞 |
| 样点超过 `±2048` 被拒绝 | P4 错把 FIR 后 S16 协议范围当成原始 12 bit 范围 |

## 11. 当前 FPGA 对 P4 的最终契约

P4 可以把 FPGA 侧视为以下确定性数据源：

```text
输入：AD9226通道A，65 MSPS，12 bit offset binary
处理：位序/码型归一化 + 三级线性相位FIR + /16抽取
输出：4.0625 MS/s、单通道S16_LE、每帧8192个连续码值
节奏：每50 ms投递一帧；帧内窗口2.016492 ms；相邻帧不连续
传输：12个CSLP WAVE_DATA/帧，UDP，无重传，主发P4并镜像电脑
时间：timestamp为首样点等效ADC时刻，已补偿694 tick FIR群延迟
校准：元数据25030 / 516 µV/code / -6761 µV，仅含标量校准
异常：OTR→ADC_OVERRANGE；数字链溢出→FIFO_OVERFLOW
不提供：原始65 MSPS流、通道B、FFT、频率、幅值、RMS、Vpp、在线逐频补偿
```

只要 P4 严格按这份契约重组和解释样点，FPGA 端就不需要为 FFT 或显示逻辑再增加隐式
处理。后续若帧长、采样率、FIR、模拟前端或校准资产发生任何变化，必须生成新的明确
Profile/校准身份并重新联合验收，不能只改一个常量让两端“差不多能跑”。
