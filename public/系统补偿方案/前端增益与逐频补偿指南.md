# CycleScope 前端增益与逐频补偿指南

## 1. 状态、范围与结论

- 状态：当前硬件与校准事实说明；P4 逐频补偿为后续实现要求，尚未落地。
- 适用范围：BNC 输入、AD8065 模拟前端、AD9226、FPGA FIR/抽取、Zynq PS CSLP 封包和 ESP32-P4 测量显示。
- 配套文档：[模拟前端放大器调试注意事项](../模拟前端放大器调试注意事项.md)、[信号前端测量方案](./信号前端测量方案.md)、[CSLP G题采样与处理 Profile v0.1](../CSLP-G题采样与处理-Profile-v0.1.md)、[CSLP UDP 通信协议 v0.1](../CSLP-UDP-通信协议-v0.1.md)。

先把结论钉死，免得后续又把三件不同的事搅在一起：

1. **实际模拟放大**发生在 AD8065 前端；它不是 FPGA 或 P4 算出来的。
2. **ADC 码值折算为 BNC 输入端电压**当前在 P4 中按 CSLP 元数据的标量比例完成。
3. **10～500 kHz 的逐频增益补偿目前没有进入 FPGA 或 P4 在线代码**；它只存在于离线校准的 `response.csv` 中。Zynq 构建会校验该文件的身份，但只向固件注入标量 `scale_uV_per_lsb`、`offset_uV` 和 `calibration_id`。

本指南不改变 CSLP 线上字段，也不建议把逐频补偿错误地下沉为“每个时域样点乘一个不同系数”。频率相关的幅值补偿应在 P4 识别并精修谱线频率后按分量完成，或另行设计、验证真正的数字均衡器。

## 2. 全链路中各层的职责

```text
BNC 输入电压 uIN
    ↓  AD8065 + 输出匹配网络：物理放大/分压
AD9226 输入电压 uADC
    ↓  ADC：量化为有符号码值 code
FPGA：码型/极性归一化 → FIR低通 → /16抽取
    ↓  保持码值尺度，不按模拟前端增益作电压换算
Zynq PS：把比例、偏置、校准身份写入每帧 CSLP WAVE 元数据
    ↓  scale_uV_per_lsb / offset_uV / calibration_id
ESP32-P4：码值→输入端电压标量换算 → FFT/投影/测量
    ↓  后续在谱线频率已知后执行逐频幅值补偿
显示：谱线幅值、RMS、Vpp 和频谱图
```

FPGA FIR 的职责是抗混叠、抑制干扰并保持已定义的数字增益；它不应秘密承担前端模拟增益补偿。这样校准身份、原始码值和滤波器验收才能各自可追溯。

## 3. AD8065 模拟前端增益

### 3.1 理论计算

当前前端是同相放大结构，反馈电阻为：

```text
RF = 1.608 kΩ
RG = 200.2 Ω
```

若反馈取样点位于输出串联匹配电阻之前，运放输出引脚的理论反馈增益为：

```text
Gfb = 1 + RF / RG
    = 1 + 1608 / 200.2
    = 9.031968032 V/V
```

若运放输出串联电阻 `RS≈50 Ω`，AD9226 输入等效负载 `RL≈50 Ω`，匹配网络分压为：

```text
Kmatch = RL / (RS + RL)
       = 50 / (50 + 50)
       = 0.5

Gamp = Gfb × Kmatch
     = 4.515984016 V/V
```

也就是说，理想条件下：

```text
uADC ≈ 4.515984016 × uIN
```

### 3.2 三种数值不能混用

| 数值 | 用途 | 能否直接写入校准 |
|---|---|---|
| `Gfb = 9.032` | 运放反馈网络理论增益 | 否；只用于拓扑与余量核算 |
| `Gamp = 4.516` | 精确50 Ω假设下的ADC节点理论加载增益 | 否；只用于理论量程核算 |
| 示波器目测约4倍 | 初步上板观察 | 否；不能当作硬件常数 |
| BNC端到端校准所得比例 | 真实测量与显示 | 是；但必须绑定校准身份和证据 |

`RF` 若从匹配电阻之后的 ADC 节点反馈，以上“乘0.5”的模型不成立，必须按真实原理图重算。实际加载增益必须用真实 BNC 输入节点 `Vin` 与 ADC 输入节点 `Vadc` 的实测比值确定：

```text
Gamp(f, A) = Vadc(f, A) / Vin(f, A)
```

其中 `f` 是频率，`A` 是输入幅度。10～500 kHz 的增益平坦度、温度、压缩、负载和探头都会影响最终端到端结果。

## 4. ADC 码值、标量校准与现状

### 4.1 名义码值换算

按 AD9226 模块标称 `10 Vpp / 4096 code`：

```text
ADC端名义LSB = 10 V / 4096
             = 2.44140625 mV/code
```

按理论加载增益 `Gamp=4.515984016` 折回 BNC 输入端：

```text
输入端名义LSB = 2.44140625 / 4.515984016
               = 0.540614458 mV/code
               = 540.614458 µV/code
```

这是量程预算的理论值，不是最终比赛显示比例。

### 4.2 当前验证过的标量校准

当前 AD8065 前端、AD9226、FPGA FIR/抽取链已冻结的校准身份为：

| 字段 | 当前值 | 语义 |
|---|---:|---|
| `calibration_id` | 25030 | 当前证据集的非零身份；正式帧置 `CALIBRATED` |
| `scale_uV_per_lsb` | 516 | 100 kHz 参考标量，折算到 DG 50 Ω设置/BNC 输入基准 |
| `offset_uV` | -6761 | 同一标量模型下的输入端零偏 |
| `filter_profile` | 1 | `G_BAND_500K_DECIM16` |
| 抽取后采样率 | 4,062,500 sample/s | 65 MSPS 经 `/16` |
| 当前已验证帧长 | 8192 | 25030证据只绑定此帧长 |

当前P4使用的标量公式为：

```text
u_input_uV = code × scale_uV_per_lsb + offset_uV
           = code × 516 - 6761
```

P4 先求整帧均值并去直流，因此常量 `offset_uV` 对纯交流谱线、RMS 和 Vpp 的最终幅度通常会抵消；它仍必须保留，用于输入端零偏的可追溯表达和波形直流语义。

## 5. 当前实现边界

### 5.1 已经在线执行的内容

1. FPGA 完成码型/极性归一化、FIR 低通和16倍抽取，但不根据AD8065增益修改样点比例。
2. Zynq PS 在每个 WAVE_DATA 的元数据中写入 `scale_uV_per_lsb`、`offset_uV` 和 `calibration_id`。
3. P4 在FFT加窗前把码值按标量换算为伏特，去直流后进行FFT、频率精修、谱线投影、RMS和Vpp计算。

### 5.2 尚未在线执行的内容

当前P4没有：

- 加载或保存 `response.csv`；
- 按频率查表；
- 在锚点间插值；
- 用逐频比例修改谱线幅值；
- 用逐频校正后的幅值重新计算RMS和Vpp。

当前构建脚本仅验证校准清单中 `response.csv` 的 SHA-256，并将三个标量注入Zynq固件。文件被哈希绑定不等于该表已经被P4使用。

离线原始证据位于：

```text
tool-of-rei/evidence/
  m11-real-frontend-20260731/offline/calibration-v1/
    calibration.json
    response.csv
    uncertainty.json
    holdout-report.json
```

该路径用于追溯，不是P4固件资产。新校准产生后，不能只替换这个目录中的文件而继续沿用旧的 `calibration_id` 或旧P4查表。

## 6. 10～500 kHz 逐频响应表

下表是当前 `calibration_id=25030` 的说明性快照。`S(f)` 是 `response.csv` 中的 `input_uv_per_code`；`K(f)` 相对于P4当前标量 `Sref=516 µV/code`：

```text
K(f) = S(f) / Sref
```

| 频率 | `S(f)`：输入端 µV/code | `K(f)`：相对516补偿 |
|---:|---:|---:|
| 10 kHz | 517.366488 | 1.002648 |
| 10.5 kHz | 517.393029 | 1.002700 |
| 20 kHz | 516.760334 | 1.001474 |
| 50 kHz | 517.035321 | 1.002006 |
| 100 kHz | 515.734541 | 0.999486 |
| 200 kHz | 520.582245 | 1.008880 |
| 300 kHz | 521.692031 | 1.011031 |
| 400 kHz | 522.402565 | 1.012408 |
| 450 kHz | 524.159857 | 1.015814 |
| 475 kHz | 524.429418 | 1.016336 |
| 490 kHz | 524.592281 | 1.016652 |
| 500 kHz | 524.612077 | 1.016690 |

在100 kHz附近，516 µV/code标量已接近本表值；到500 kHz，逐频补偿约为 `+1.669%`。这对250 mV量级的谱线可接近数mV，已经足以影响5 mV误差门限，不能以“变化看起来不大”为理由忽略。

表中的相位列 `analog_ch2_minus_ch1_phase_deg` 只代表同次采集中模拟前端 CH2 相对 CH1 的相位响应；DG4202和FPGA没有共同触发，因此它不是端到端绝对相位。当前不应把该列直接用于报告绝对相位，亦不应据此声称已经完成完整波形去嵌入。

## 7. P4逐频幅值补偿的正确位置

### 7.1 为什么不是时域逐点乘法

每个时域样点同时包含基波和谐波，不能根据“这个样点属于哪个频率”选一个增益系数。若要在时域完成逐频校正，本质上需要额外设计、量化并验证一个数字均衡器；它还会影响FIR阻带和噪声。

对本题“基波 + 1或2个谐波”的信号，推荐在P4完成FFT、频率精修和正弦投影后，对每个已识别分量做标量幅值补偿。这几乎不增加计算量，且不会改变FPGA的抗干扰滤波器。

### 7.2 冻结的处理位置和公式

在P4 `FftProcessor` 中，先执行：

```text
码值 → 516 µV/code 标量换算 → 去直流 → FFT
→ 候选峰选择 → 基频精修 → project_at_frequency()
```

`project_at_frequency()`已经得到每个分量的精确频率 `f` 和当前标量幅值 `A_scalar(f)`。在它返回后、写入 `spectral_lines` 以及累计RMS/Vpp前执行：

```text
S(f) = 在相邻两个 response.csv 锚点间，对 input_uv_per_code 做分段线性插值
K(f) = S(f) / 516
A_corrected(f) = A_scalar(f) × K(f)
```

插值规则固定如下：

1. 只接受 `10,000 Hz ≤ f ≤ 500,000 Hz`。
2. 命中锚点时直接取锚点值。
3. 锚点之间对 `input_uv_per_code` 按频率分段线性插值。
4. 区间外不外推；低于10 kHz或高于500 kHz的分量不能使用25030逐频表作为测量补偿。
5. 1 MHz以上的阻带、干扰残余和混叠诊断分量绝不逆补偿。

峰值检测、候选排序和SNR门槛可以继续使用未逐频补偿的标量频谱，避免校准表轻微起伏改变检测策略；显示与测量发布时使用校正后的语义谱线幅值。

### 7.3 RMS、Vpp与显示的连带更新

对确认的互不相同正弦分量，使用校正后的峰值幅度重算：

```text
RMS = sqrt( Σ(A_corrected,i² / 2) )
```

Vpp必须用校正后的各分量振幅和当前测得的相对相位重建，而不是继续使用未校正的时域最大最小值。若未来要校正不同频率间的相位畸变，必须另行验证相对相位表的来源与不确定度；本指南只冻结幅值补偿。

频谱图若按完整bin绘制幅值，可在显示投影时对10～500 kHz内每个bin使用同一插值规则；带外bin保持未补偿诊断值。不得为了视觉平滑把补偿后的带外噪声、阻带残余放大。

## 8. 校准身份与变更纪律

逐频表必须和以下条件原子绑定：

- `calibration_id`；
- AD8065版本、反馈/匹配电阻和负载拓扑；
- AD9226通道、码型、输入范围和偏置；
- FPGA bitstream、`filter_profile`和抽取后采样率；
- 帧长/FFT Profile；
- 信号源50 Ω设置和BNC输入基准；
- `response.csv`、不确定度报告、holdout报告及SHA-256。

当前 `calibration_id=25030` 的证据绑定 `8192点 / 4.0625 MS/s / filter_profile=1`。16384或32768点模式在没有重新验证并分配新身份前，只能使用未校准或明确标注的标量结果，不能偷偷继承25030的逐频表。

每次更换放大模块、电阻、模拟滤波器、ADC通道、负载方式、数字滤波配置或校准采集基准时，必须：

1. 重新获得BNC端到端训练点和独立holdout点；
2. 生成新的 `response.csv`、不确定度和校准清单；
3. 分配新的非零 `calibration_id`；
4. 从已验证表生成P4运行时查表资产；
5. 用新的身份完成P4谱线、RMS、Vpp和带外不补偿门禁。

公开本文中的数值是当前身份的说明快照，不是第二份可手工维护的运行时数据源。P4将来使用的查表资产必须由已验证 `response.csv` 自动生成，并与同一 `calibration_id` 一起编译或校验。

### 9.2 未来P4逐频补偿

- [ ] 运行时表由已验证 `response.csv` 自动生成，不手写第二份常量表。

- [ ] 新Profile、新bitstream或新前端不能复用25030表，除非完成独立验证并分配新身份。

## 10. 不要做的事

- 不要把理论 `4.516`、示波器目测“约4倍”和端到端 `516 µV/code` 当作同一个数。
- 不要在FPGA中为了“补偿增益”随意放大滤波后码值，破坏量程、溢出和校准语义。
- 不要把 `CALIBRATED` 标志理解为已经进行了逐频补偿。
- 不要对1 MHz以上干扰、阻带残余或未知混叠分量做逆补偿。
- 不要在未重新验证的16384/32768点模式中沿用8192点的25030逐频表。
