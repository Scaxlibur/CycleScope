## 证据与发布边界

- 问题：完整 M8/M9 20 例审计绑定应用 BIN d819641d…d8207007，而当前 F0 两位小数显示镜像为 e30d16c4…a4bac0e。
  - 影响：新镜像已完成格式/参数回归、fresh build、烧录校验和真实 FPGA 100 帧烟测，但不能在未重跑同等物理矩阵前被写成“已完成20例发布审计”。
  - 规避：交接时使用 public/测试与证据索引.md 和 public/evidence/F0显示版构建烧录证明/release-record.json 明确区分两个构建身份。
  - 状态：边界已记录，原始两个证据根均保留；若需要把新镜像提升为发布身份，再追加受控审计。

## 高风险
- 问题：硬件在 `450 mVpp` 档存在已确认的模拟前级压缩；用户后续实测最大不失真输入约为 `380 mVpp`，但该实测边界不等于正式量程。
  - 影响：若未来有人绕过范围声明继续使用450 mVpp，10 kHz历史点的端到端增益变化为 `-3.1224%`，CH2/FPGA THD约 `4.37%/4.46%`，一维逐频补偿不能修复这种非线性。该风险不影响已冻结的 `≤250 mVpp` 普通范围；最终1 MHz干扰例外总包络仅 `265.080892 mVpp`，低于380 mVpp实测边界。
  - 规避：UI/文档/验收不得把380 mVpp实测边界宣称成正式连续量程；三个450 mVpp案例只作历史证据，不参与fit、holdout或验收。若未来确需扩大正式范围，必须新建证据根从M2重标，不能把压缩点重新塞进当前profile或二维补偿。
  - 状态：`scope-amendment-v2` 已冻结正式上限和排除清单，原 `campaign-stop.json` 保留不改写；profile `0xC5DCDE41` 已通过7点独立保留验证及最终M8/M9 20例验收。旧RTM CH1/Ksrc诊断仅解释历史接线，不再是当前以DG设置为正式真值的阻断项。

- 问题：AD9226 MODE/DFS 码型、模拟极性和 OTR 接线尚未由原理图/实测冻结。
  - 影响：可能造成符号、零点、一 LSB 偏差或无法识别超量程，影响 5 mV 精度。
  - 规避：用直流、斜坡、正弦验证 straight binary/补码与极性，并让 OTR 与数据流水线对齐。
  - 状态：待硬件确认。

- 问题：系统完全启动、LAN 会话已建立并持续分析后，TIME/FFT/1P/3P 按键到对应内容真正上屏不超过 2 秒尚无端到端取证。
  - 影响：20 Hz 下一帧约 50 ms、FFT 长测平均/最大 `17.491/50.210 ms` 显示出充足分段预算，但该 FFT 计时不含频谱/1P/3P 投影、latest queue、250 ms UI 轮询、画布渲染和 panel flush；自动 UI bridge 也不能证明触摸事件到面板刷新完成时刻，当前仍不能宣称 G 题 2 秒视觉验收 PASS。
  - 规避：保留安全 PHY 时序和自动协商默认路径；系统完全启动后，在电脑合成数据持续输入时逐项记录按键、渲染与面板刷新完成时刻，并保存连续视频/照片，每项均不得超过 2 秒。启动时间不属于该窗口，当前无需继续优化 PHY 冷启动。
  - 状态：最终 `P4CAL C5DCDE41` 数值审计20/20 PASS；三谱线连续分析曾暴露IDLE1看门狗，现以每帧2 ms协作阻塞修复并通过完整11例复测。normal v5 冷启动约 `4.25 s` 进入 UI RUNNING，Display-only v8最大软件回调 `18.827 ms`；这些仍只证明软件预算充足，人工按键到真实 panel flush 取证尚未完成。

## 中低风险

- 问题：现有 51 份 real-adc pcap 都是单频测量点，不能直接满足 P4 的至少两根题目谱线门禁。
  - 影响：原包精确重放可以验证握手、来源、CRC、12 包重组和单线 fail-closed，但会得到 `valid=0 lines=1`，不能单独验证 measurement/UI LIVE。
  - 规避：补采 FPGA 同时双/三谐波的原始 pcap。当前样点相加的 H1+H10 派生测试只用于验证 P4 数字分析/UI，必须标注 `NOT_SIMULTANEOUS_FPGA_CAPTURE`，不得冒充真实前端双音。
  - 状态：单音 session `01B1B679` 23/23 帧预期拒绝；派生 session `29E84C98` 23 帧 measurement/UI 闭环，证据边界已写入项目快照。

- 问题：现有高阶 6×100 解析器主要校验六个 session 的 frame 1/100 measurement，没有跨文件冻结 sender、ELF、累计 600 全链 health 和篡改负例。
  - 影响：原始 sender/UART 人工证据支持每例 100 帧及累计 600，但“严格 6×100 防伪闭环”表述过强，孤立伪造 12 条 measurement 的日志可能越过当前解析器。
  - 规避：按 10k evidence 模式绑定六份 sender、UART、镜像身份、session/boot/config、累计 completed/analyzed/published=600、错误 health 和 final STALE，并增加对抗篡改测试。
  - 状态：报告已降级为端点验证/人工原始证据；严格 evidence 尚待补齐。

- 问题：现场可指定的 H2～H50 任意合法阶次与全相位组合尚未系统遍历。
  - 影响：当前 host/板测覆盖 H2/3/4/5/6/18/19/20/46/47/49/50 等高风险点，但候选池固定为 12 个且有相对/绝对幅值门限；在未覆盖阶次、泄漏或杂散下，3 音输入可能只选出 2 根仍判 valid，造成少画一根且 Vpp/RMS 漏项。
  - 规避：主机遍历 H2～H50 合法阶次、H1/谐波最弱、2/3 音和多组相对相位，再在 P4 抽测最坏组合；对 3 音缺线增加明确门禁前，应先评估真实噪声下误报/漏报权衡。
  - 状态：已有弱 5 mV、H49/H50、500 kHz 与 66 例相位强证据，但不能外推为全组合证明。

- 问题：同一 CSLP session 内重配置后 `frame_id` 是否必须持续单调尚未在协议文档冻结。
  - 影响：analysis cursor 只含 session/frame；若 FPGA 在同 session 的 CONFIG/ENABLE 后把 frame_id 重置为 1，P4 会拒绝这些低帧号直到超过旧 cursor。现有 DISABLE 测试使用 9→11 连续编号，没有覆盖重置语义。
  - 规避：优先在 wire contract 明确“整个 session 内 frame_id 跨 config 单调”；若协议允许重置，则 cursor 必须加入 config/epoch，并补同 session 重配置恢复测试。
  - 状态：当前电脑 emulator 与既有测试均保持 session 内单调；真实 FPGA 合约待确认。

- 问题：时域纵轴按每帧 extrema×1.15 连续自动缩放，没有固定档位或迟滞。
  - 影响：真实量化噪声、残余或轻微相位漂移可能让 1P/3P 纵轴与波形大小逐帧抖动；现有固定向量/相位投影测试不能证明带噪序列的视觉稳定性。
  - 规避：先做带小幅噪声和相位漂移的序列测试并记录纵轴变化；若人工观感不稳，再采用固定档位与迟滞，保持 1P/3P 同帧同档。
  - 状态：数值与相位锚定路径已通过，动态视觉稳定性待测。

- 问题：normal v5 的 10,000 帧运行出现一次 FFT 最大值 `50.210 ms`，略高于 50 ms 帧周期，也高于“通常约 15～25 ms”的描述。
  - 影响：不能声称每帧 FFT 始终在 25 ms 内或严格小于一帧周期；若把旧 `<50 ms` 解析门限当成产品判据，会误把一次无业务后果的调度长尾判成整机失败。
  - 规避：同时报告平均值和真实最大值，以 acquired/analyzed/published、stale/invalid/failure、按键后 2 秒及真实 panel flush 为业务门禁；若长尾频繁出现或导致计数脱节，再单独做调度跟踪，不能篡改日志或抬高平均值掩盖。
  - 状态：本轮最终平均 `17.491 ms`，最大 `50.210 ms`；10,000 帧仍全部分析/发布，stale/invalid/FFT failure 为 0，内存稳定。该观察保留为低风险长尾，不直接判失败。

- 问题：LAN 实时数据下的完整周期、频谱视觉及 G 题实物条件尚未人工验收。
  - 影响：自动日志与历史 TIME/FFT、1P/3P 切换烟测不能证明最终 LAN 链的完整周期、谱线相对高度和触摸观感，也不能证明单路 5 V、≥6 英寸屏、板上 BNC/50Ω 线缆符合要求。
  - 规避：后续由用户在三类 G 题输入下逐项操作，结合上方按键到面板刷新计时，并核对供电、屏幕尺寸、BNC 座和 50Ω 线缆；人工测试前不得宣称 LVGL/整机完成。
  - 状态：程序化状态机、1P/3P span、语义谱线坐标/弱线高度和跨相位稳定性均已有自动证据；真实 panel flush、肉眼观感及实物条件仍按用户要求暂缓。

- 问题：FPGA `.2` ICMP 在线但未回应 CSLP 时，receiver 约每秒重新握手并输出 timeout 日志。
  - 影响：正式管线不会生成本地假测量，但密集握手日志可能掩盖其他告警并产生不必要的重试开销。
  - 规避：本轮先让 FPGA responder 正常回应以完成联调；指数退避与日志限流留作低优先级优化，不阻塞当前两板验收。
  - 状态：正式 `.2` 镜像 45 秒内复现 42 次 timeout；按用户要求不再无限优化 ESP32-P4 端。

- 问题：ESP-DSP 的 ESP32-P4 ARP4 FFT 内核对 10 kHz、弱基波、特定相位输入产生错误正谱，不能重新启用。
  - 影响：exact 50 mVpp 向量在 ARP4 下 100/100 帧均为 `valid=0 lines=1`；把单谱线放宽为有效会误把 20 kHz 二次谐波当基频，属于伪修复。
  - 规避：生产分析调用固定为 `dsps_fft2r_fc32_ansi`；恢复 ARP4 前必须用 exact 向量做目标端 A/B，并重跑四例在线矩阵与性能回归。不得裸降阈值或放宽最少两谱线门槛。
  - 状态：normal v5 的 ANSI 6×100 高阶矩阵与 10,000 帧全链回归 PASS；exact 向量启动门禁现同时检查 H1 phase，CRC/两谱线/F0/phase/Vpp/RMS/H1/H2/bin/FFT 时限任一失败都会 fail-closed。最新 v5 启动日志中的 exact 门禁约 `13.9 ms`。

- 问题：LVGL latest-result 定时器当前为 250 ms，即画面最多约 4 Hz；网络与分析仍为 20 frame/s。
  - 影响：数值和所有权正确，但尚未人工确认 4 Hz 动态波形是否满足“稳定显示”的评审观感。
  - 规避：先完成 4 Hz 人工验收；若需要提高刷新率，再基于 RGB565 canvas 的实测 CPU/UI gap 调到 100 或 50 ms，不能盲改。
  - 状态：final P4CAL 11例续跑及此前normal v5 10,000帧均无最终残留WDT，单session历史 `max_ui_gap=258 ms`；待人工视觉取舍。

- 问题：当前 `max_ui_gap` 在 session 变化时清零，会隐藏模拟器离线到重连首帧之间的全局停顿。
  - 影响：单 session 的 4 Hz UI 吞吐统计有效，但不能拿该字段证明跨 session 连续可用性。
  - 规避：后续同时记录全局 gap 与 session 内 gap；本轮修复请求连续被自动审核拦下，按用户要求停止重试。
  - 状态：已登记，不影响单 session 600/10,000 帧数据链结论。

- 问题：MIPI-DSI 初始化报告 `on_frame_buf_complete unavailable`。
  - 影响：buffer-switch release/dummy-draw 路径可能不可用。
  - 规避：继续使用已验证的普通刷新路径；最终自动稳定性已完成，后续只在人工 M7 中核对长时画面观感与刷新异常。
  - 状态：最终 ANSI 镜像 36,000 帧/30 分钟无 WDT、panic、复位或内存持续下降，自动项 PASS；人工 M7 待测。

- 问题：`esp_codec_dev` 1.5.11 发布包有 CMake 语法错误。
  - 影响：解除依赖锁或升级时可能重新构建失败。
  - 规避：`idf_component.yml` 精确锁定 1.5.10，升级前单独验证。
  - 状态：当前锁定有效。

- 问题：外部协议文档仍标记为“设计草案”，且用 `acquire_latest(after_frame_id)` 简写，未体现已落地的 session-aware `FrameCursor`。
  - 影响：状态描述过期，调用者照抄还可能在 FPGA 重启后忽略低 frame_id 新 session。
  - 规避：`public/` 本轮只读；后续由文档维护阶段更新，当前以 wire format、源码 API 和本快照为准。
  - 状态：wire format 不受影响。

- 问题：Display 正常生命周期已闭环，但 BSP `bsp_touch_delete()` / `bsp_display_delete()` 返回 `void`，adapter 0.6.2 的 LCD/touch callback 解绑失败也不会完整向产品层传播。
  - 影响：产品层可验证正常 teardown、heap/integrity、重复硬件创建和日志，但无法证明任意底层 delete/callback 故障后仍绝对无 ISR/UAF 或硬件句柄残留。
  - 规避：把任何 callback-clear、panel-delete、interrupt、GPIO conflict 或 teardown warning 视为失败并要求重启；升级 BSP/adapter 时优先采用可返回错误的删除 API，并重跑 D0/D3～D9。不得把高层 `owned=EMPTY` 单独外推为不可观测故障也安全。
  - 状态：正常 `-O2` v6 的 D0、D3～D9、D1/D2、同对象 retry 与最终 teardown 全部 PASS，日志未出现上述错误；这是当前实测成功边界，不覆盖被上游吞掉的假设故障。

- 问题：`receiver.start()` 成功后，`app.connect()` 仍可能因 UI timer 或 analysis task 创建失败而返回 false，而 receiver 没有 stop/join。
  - 影响：当前启动顺序已保证 Display、UI 和 FFT prepare 失败时 receiver 从未启动，但最后这个窄窗口仍可能留下运行中的 Ethernet/socket/receiver task，而正式 pipeline 离线。
  - 规避：维持 `display → UI → FFT prepare → receiver → connect` 顺序；若未来要求该最后窗口也可同次恢复，需先为 pipeline 和 receiver 实现协作式 stop/join，再按 timer → pipeline → receiver → network 逆序退出，不能复用当前只适合启动期的 rollback。
  - 状态：最新正常 600 帧回归未触发；作为剩余生命周期边界登记。

- 问题：socket `close()` 返回失败时当前会计数并放弃本地 fd 所有权，尚无安全故障注入。
  - 影响：本轮 33 次 fatal、两次 setup 失败及正常运行中的所有 close 都返回 0；但若未来 lwIP 真正返回非零，不能由现有证据证明 fd 已释放，也不能盲目重试一个可能已关闭并被跨核复用的编号。
  - 规避：把 `socket_close_failures != 0` 视为明确健康告警；后续先核对 IDF/lwIP close 的失败语义，再用受控 wrapper 单独验证，不用“先 close 再 recv”或直接重试旁路。
  - 状态：未观察到实际故障，非 RT1～RT4 阻断项；已列入 Backlog。

- 问题：当前固定 Profile 没有面向用户的运行时重配置入口。
  - 影响：`run_disable_push()` 与同 session `DISABLE→CONFIG→ENABLE` 已实现并精确测试，但正常固定配置运行中不会主动触发；未来新增采样 Profile 切换时必须在 receiver task 单所有者上下文复用该序列，不能让 UI 任务直接操作 socket。
  - 规避：保持 test-only 触发默认关闭；新增真实 Profile 切换时只投递请求给 receiver task，并重跑 ACK-loss、旧 config 门禁与恢复矩阵。
  - 状态：协议生命周期本身 PASS；生产当前无动态 Profile 需求。

- 问题：电脑 `.5` 为临时地址，CP2102N 曾出现 `-71 (EPROTO)` 和过流计数。
  - 影响：网卡重连可能丢 `.5`，USB 电气问题可能中断烧录或日志。
  - 规避：不碰 `.4`；需要时恢复 `.5`。USB 再报错先检查供电、线材和端口。
  - 状态：最近一轮网络与串口正常。
