## 冻结硬件与软件基线
- ESP32-P4 Function EV Board revision v1.0，CPU 360 MHz，16 MB Flash，32 MB PSRAM。

- ADC：单颗 AD9226 通道 A，原始 65 MSPS；不采用双 ADC 130 MSPS 交织。

## 冻结 Profile 1 与 CSLP
- FPGA 先低通并 16 倍抽取，线上样点率 4,062,500 S/s。
- 每帧 8192 个 S16_LE 样点，采集窗约 2.016 ms，FFT 栅格约 495.910645 Hz。
- 异步投递周期 50 ms（20 frame/s）；WAVE_DATA 应用头 72 字节，每帧固定 12 个 UDP 包。
- 控制面使用应用层 ACK、100 ms 超时、最多 3 次重试和同序号幂等缓存。
- 数据面无 FRAME_ACK、重传或背压；坏包/缺片丢整帧并保留上一有效结果。
- 三缓冲角色为 assembling/latest/in_use；未采用的 latest 可覆盖，InUse 绝不覆盖。
- 消费 API：`acquire_latest(FrameCursor{session_id, frame_id})` → 处理 → `frame_is_current()` → 发布 → `release()`。

## 组合架构

```text
CSLP receiver（Core 1，priority 6）
  → assembling/latest/in_use 三缓冲
  → 唯一正式 mailbox consumer（Core 1，priority 4）
  → esp-dsp 8192 点 FFT/测量 + 独立 1P/3P 包络投影
  → 4097 Bin→640 列频谱 + 640 列时域包络
  → 深度 1 latest 结果队列
  → LVGL worker/UI（Core 0）
```

- `LiveDataPipeline` 已删除周期性本地 sample source 与 raw queue；启动时临时自检帧只验证 FFT，不发布到 UI，随后立即释放。
- 分析任务同时最多持有一个 `FrameView`，RAII 保证所有失败/过期路径 release；游标在 acquire 后立即前移，发布前紧邻调用 `frame_is_current()`。
- Fs、scale、offset、config/session/frame/timestamp/calibration/flags 全部来自 CSLP 元数据；新 session 不再因 frame_id 重用被 UI 误判。
- 网络 receiver priority 6 高于 analysis priority 4，保持收包可抢占计算。
- LVGL API 只能在 Core 0/UI 上下文调用；网络和分析任务不得持有 LVGL 对象。
- 冷启动时 Core 1 一次性 bootstrap 独占 `receiver.start()`；Core 0 同时建立 UI 壳，并在 LVGL 锁外 prepare FFT/self-test。静态二值信号量发布 receiver 结果后才创建 analysis task，READY 前不会访问 receiver frame API。
- `LiveDataPipeline::prepare()` 与 `start(receiver)` 两阶段分离；prepare 失败会删除 queue/frame 并显式 deinitialize FFT，正常路径只初始化一次。`sdkconfig.defaults` 固化 app_main Core 0 与 FreeRTOS 静态分配。
